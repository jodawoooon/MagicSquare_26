# MagicSquare Cursor Rules + User Entity 작업 보고서

## 1) 작업 개요

- 목적: MagicSquare 프로젝트에 맞는 `.cursorrules`를 구성하고, ECB 패턴 기반 `User` 엔티티와 테스트를 구축
- 기준: Python 3.10+, PEP8, type hints 필수, Google docstring, pytest + AAA, TDD 단계 준수

## 2) 수행 순서

1. `.cursorrules` 뼈대 생성
2. `tdd_rules` 섹션 상세화
3. 전체 빈 섹션(`project`, `code_style`, `architecture`, `testing`, `forbidden`, `file_structure`, `ai_behavior`) 채움
4. `.cursorrules` 검토 수행(문법/누락/충돌/실행 가능성 관점)
5. ECB `entity` 레이어에 `User` 엔티티 구현
6. `tests/entity/test_user.py` 작성(pytest + AAA)
7. 테스트 실행 및 lint 확인

## 3) 산출물

### 3.1 규칙 파일

- `.cursorrules`
  - `tdd_rules`를 `red_phase`, `green_phase`, `refactor_phase`로 세분화
  - `forbidden` 항목을 `pattern/reason/alternative` 구조로 정의
  - `ai_behavior`의 전/중/후 생성 규칙 명시

### 3.2 코드 파일

- `entity/user.py`
  - `User` dataclass 엔티티
  - 상태/이름 변경 메서드(`activate`, `deactivate`, `rename`)
  - 도메인 불변식 검증(`user_id`, `name` 공백/빈 값 금지)
  - 모든 메서드 타입힌트 + Google 스타일 docstring 적용
- `entity/__init__.py`
  - `User` export

### 3.3 테스트 파일

- `tests/entity/test_user.py`
  - 생성/비활성화/이름변경 정상 시나리오
  - 잘못된 `user_id`, `name`에 대한 `ValueError` 예외 시나리오
  - AAA 패턴 주석 기반 구조

## 4) 검증 결과

- 테스트 실행:
  - `python -m pytest -q`
  - 결과: `7 passed`
- 린트 확인:
  - 수정 파일 기준 lint 이슈 없음

## 5) 적용된 설계 원칙

- ECB 의존 방향 준수: `entity`는 외부 레이어(`control`, `boundary`)에 의존하지 않음
- TDD 지향 흐름 반영: 테스트 파일 작성 후 구현 및 검증
- 코드 품질 기준 반영: 타입힌트/문서화/PEP8 호환 형식 유지
