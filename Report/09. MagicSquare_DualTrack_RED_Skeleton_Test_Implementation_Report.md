## 5) RED 스켈레톤 규칙 적용

| 규칙 | 적용 내용 |
|---|---|
| AAA | Given/When/Then **주석만**; Act/Assert 코드 없음 |
| naming | `test_<test_id>_<scenario>` (예: `test_u_in_04_three_blanks_returns_e002`) |
| 본문 | `pytest.fail("RED: <Test ID> — <한 줄 설계 요약>")` 단일 실패 |
| production import | 모듈 상단 **활성** import (Report/05와 동일 정책) |
| Track A Mock | U-OUT/U-FLOW — Control `execute` stub/spy **주석**; Domain mock 금지 |
| Track B | Domain mock **금지** |
| D-SOL-02 | `pytest.fail("RED: D-SOL-02 — G2 TBD")` — G2 확정 전 표시 |

## 8) 검증 결과 (RED 실행)

### 8.1 실행 명령

```bash
python -m pytest tests/boundary/test_u_in_04_08_input_validation.py \
  tests/boundary/test_u_out_01_03_output_contract.py \
  tests/boundary/test_u_flow_02_execute_zero_calls.py \
  tests/entity/test_d_loc_01_blank_coords.py \
  tests/entity/test_d_mis_01_missing_numbers.py \
  tests/entity/test_d_val_01_06_magic_square.py \
  tests/entity/test_d_sol_01_04_solution.py -v --tb=line
```

### 8.2 결과 요약 (2026-05-29)

| 구분 | 건수 | 원인 |
|---|---|---|
| **collection ERROR** | 7 (파일 단위) | `ModuleNotFoundError` — `boundary.*`, `entity.services.*`, `control.solver` 미구현 |
| **FAILED** (`pytest.fail`) | 0 | import 단계에서 수집 중단 |
| **PASSED** | 0 | — |
| **설계상 테스트 수** | 24 | import 해소 후 `pytest.fail` → FAILED 예상 |

### 8.3 실패 분석 결론

- 실패는 **비즈니스 로직 버그가 아님** — ECB 프로덕션 패키지·모듈 경로 미구현
- production import를 **주석 처리하지 않음** — collection ERROR도 유효한 RED
- GREEN 시 import 성공 후 각 테스트는 `pytest.fail` → assert 구현으로 **FAILED → PASSED** 전환 예상
