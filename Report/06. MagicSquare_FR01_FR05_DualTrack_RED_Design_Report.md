## 4) 프로젝트 계약 요약

### 4.1 입출력

| 항목 | 규칙 |
|---|---|
| 입력 | 4×4 `int[][]`, `0`=빈칸(정확히 2개), 값 `0` 또는 `1~16`, 0 제외 중복 금지 |
| 출력 | `int[6]` = `[r1,c1,n1,r2,c2,n2]`, 좌표 **1-index** |
| Magic Constant | 4×4 → M=34 (`MagicConstant` SSOT) |

### 4.2 Boundary 검증 순서 (short-circuit)

`null` → `size` → `empty count` → `value range` → `duplicate`

### 4.3 Failure envelope (Python 예외 아님)

| code | message (exact) |
|---|---|
| E003 | `입력 행렬이 null입니다.` |
| E001 | `입력은 4x4 정수 행렬이어야 한다.` |
| E002 | `빈칸(0)은 정확히 2개여야 한다.` |
| E004 | `값은 0 또는 1~16만 허용된다.` |
| E005 | `0을 제외한 숫자는 중복될 수 없다.` |

invalid 입력 시 `SolvePartialMagicSquare.execute` **0회** (U-FLOW-02, AC-FR01-05).

> **SSOT 정합 참고:** PRD §13은 `INVALID_MATRIX_SIZE` 등 문자열 코드를 사용한다. 본 RED 설계는 사용자 프로젝트 계약 **E001~E005** 기준이며, GREEN 시 PRD 코드와 1:1 매핑 테이블 추가를 권장한다.
