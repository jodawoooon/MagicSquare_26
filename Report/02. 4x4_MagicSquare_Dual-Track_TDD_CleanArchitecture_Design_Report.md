# 4x4 Magic Square Dual-Track TDD + Clean Architecture 설계 보고서

## 1) Logic Layer (Domain Layer) 설계

### 1.1 도메인 개념

| 분류 | 이름 | 책임(SRP) | 검증 방법 |
|---|---|---|---|
| Entity | `MagicSquareBoard` | 4x4 행렬 상태 보관, 좌표 접근 규칙 제공 | `T-DOM-001`, `T-DOM-002` |
| Value Object | `CellPosition` | 1-index 좌표 표현, 범위(1~4) 보장 | `T-DOM-003` |
| Value Object | `InputMatrixSpec` | 입력 계약(크기, 값 범위, 빈칸 개수, 중복) 검증 | `T-DOM-004`~`T-DOM-008` |
| Value Object | `CandidateNumbers` | 누락 숫자 2개 계산 및 오름차순 보관 | `T-DOM-009` |
| Domain Service | `MissingCellLocator` | 빈칸 2개 위치 탐색 | `T-DOM-010` |
| Domain Service | `MagicSquareValidator` | 행/열/대각선 합 일치 판정 | `T-DOM-011`~`T-DOM-014` |
| Domain Service | `SolutionOrderingPolicy` | 두 숫자 배치 순서 정책 적용 | `T-DOM-015`, `T-DOM-016` |
| Domain Service | `MagicSquareSolver` | 유스케이스 전체 조합(탐색-검증-결과 생성) | `T-DOM-017`~`T-DOM-020` |

### 1.2 도메인 불변조건(Invariants)

| 규칙 ID | 규칙 | 실패 조건 | 실패 결과 |
|---|---|---|---|
| `R-DOM-001` | 입력은 4x4 정수 행렬이어야 한다 | 행/열 길이 불일치 | `INVALID_MATRIX_SIZE` |
| `R-DOM-002` | 값은 0 또는 1~16만 허용한다 | 범위 외 정수 존재 | `VALUE_OUT_OF_RANGE` |

| `R-DOM-006` | 완성 후보는 모든 열 합이 동일해야 한다 | 임의 열 합 불일치 | `NOT_MAGIC_SQUARE` |
| `R-DOM-007` | 완성 후보는 두 대각선 합이 동일해야 한다 | 대각선 합 불일치 | `NOT_MAGIC_SQUARE` |

## 2) Screen Layer (UI Layer) 설계 (Boundary Layer)

### 2.1 사용자/호출자 관점 시나리오

| 단계 | 입력/행위 | 처리 | 출력 |
|---|---|---|---|
| 1 | 호출자가 4x4 배열 제출 | UI Boundary 스키마 검증 | 실패 시 에러 스키마 |
| 2 | 계약 유효 | Domain 호출 | Domain 결과/오류 수신 |
| 3 | Domain 성공 | 결과 포맷 정규화 | `int[6]` 반환 |
| 4 | Domain 실패 | 오류 매핑 | 표준 에러 반환 |

### 2.2 UI 계약(외부 계약)

| 항목 | 계약 |
|---|---|
| Input schema | `matrix: int[4][4]`, 값 제약은 `R-DOM-001`~`004` 동일 |
| Output schema | `result: int[6]` = `[r1,c1,n1,r2,c2,n2]`, 좌표 1-index |
| Error schema | `{ code: string, message: string, details?: object }` |
| 오류 코드 집합 | `INVALID_MATRIX_SIZE`, `INVALID_BLANK_COUNT`, `VALUE_OUT_OF_RANGE`, `DUPLICATE_NON_ZERO_VALUE`, `NO_VALID_ASSIGNMENT`, `INTERNAL_ERROR` |

### 2.3 UI 레벨 테스트(Contract-first, RED 우선)

| 테스트 ID | 설명 | Domain Mock 동작 | 기대 결과 |
|---|---|---|---|
| `T-UI-001` | 4x4가 아닌 입력 | 호출되지 않음 | `INVALID_MATRIX_SIZE` |
| `T-UI-002` | 빈칸 개수 2개 아님 | 호출되지 않음 | `INVALID_BLANK_COUNT` |
| `T-UI-003` | 값 범위 위반 포함 | 호출되지 않음 | `VALUE_OUT_OF_RANGE` |
| `T-UI-004` | 중복 숫자 포함 | 호출되지 않음 | `DUPLICATE_NON_ZERO_VALUE` |
| `T-UI-005` | 정상 입력 + Domain 성공 | `result=int[6]` 반환 | 동일 형식 반환 |
| `T-UI-006` | Domain `NO_VALID_ASSIGNMENT` | 오류 throw/return | 표준 에러 매핑 |
| `T-UI-007` | 결과 길이 6 검증 | Domain 성공 | 길이 불일치 시 `INTERNAL_ERROR` |
| `T-UI-008` | 좌표 1-index 검증 | Domain 성공 | 범위 이탈 시 `INTERNAL_ERROR` |

### 2.4 UX/출력 규칙

| 규칙 ID | 규칙 | 검증 테스트 |
|---|---|---|
| `R-UI-001` | 모든 오류 메시지는 `[코드] 한글 설명` 형식 | `T-UI-001`~`008` |
| `R-UI-002` | 한 번에 하나의 대표 오류만 반환 | `T-UI-001`~`004` |
| `R-UI-003` | 입력 오류는 Domain 호출 전에 차단 | `T-UI-001`~`004` |
| `R-UI-004` | 성공 응답은 추가 필드 없이 결과 배열만 포함 | `T-UI-005` |

표준 오류 메시지 규칙:
- `INVALID_MATRIX_SIZE`: `[INVALID_MATRIX_SIZE] 입력은 4x4 정수 행렬이어야 합니다.`
- `INVALID_BLANK_COUNT`: `[INVALID_BLANK_COUNT] 빈칸(0)은 정확히 2개여야 합니다.`
- `VALUE_OUT_OF_RANGE`: `[VALUE_OUT_OF_RANGE] 값은 0 또는 1~16만 허용됩니다.`
- `DUPLICATE_NON_ZERO_VALUE`: `[DUPLICATE_NON_ZERO_VALUE] 0을 제외한 숫자는 중복될 수 없습니다.`

## 3) Data Layer 설계 (Data Layer)

### 3.1 목적 정의

| 항목 | 정의 |
|---|---|
| 목적 | 학습용 실행 이력 관리(입력 재현, 회귀 테스트 재사용) |
| 범위 | 입력 행렬 저장/로드, 선택적으로 결과 저장 |
| 비범위 | 트랜잭션, 동시성 제어, 원격 DB |

### 3.2 인터페이스 계약

| 인터페이스 | 입력 | 출력 | 실패 |
|---|---|---|---|
| `saveInput(matrix, metadata)` | 검증된 4x4 행렬 + 메타 | `savedId` | `DATA_WRITE_FAILED` |
| `loadInput(savedId)` | 식별자 | 4x4 행렬 | `DATA_NOT_FOUND`,`DATA_FORMAT_ERROR` |
| `saveResult(savedId, result6)` | 식별자 + `int[6]` | `void` | `DATA_WRITE_FAILED` |
| `loadResult(savedId)` | 식별자 | `int[6]` | `DATA_NOT_FOUND`,`DATA_FORMAT_ERROR` |

### 3.3 구현 옵션 비교(메모리/파일)

| 옵션 | 장점 | 단점 | 적합도 |
|---|---|---|---|
| A. InMemory | 구현 단순, 테스트 속도 빠름, 외부 의존성 없음 | 프로세스 종료 시 데이터 소실 | 단위 테스트 최적 |
| B. File(JSON/CSV) | 실행 간 데이터 유지, 수동 검증 쉬움 | 파일 I/O 예외 처리 필요, 포맷 오류 가능 | 통합 테스트 유리 |

추천안: **A(InMemory) 우선**
- 이유 1: TDD 학습 목표(빠른 RED-GREEN-REFACTOR 반복)에 가장 유리하다.
- 이유 2: 알고리즘/계약 훈련에 집중 가능하며 데이터 영속성 복잡도를 분리할 수 있다.
- 이유 3: 이후 어댑터 교체로 B를 추가해도 Domain/UI 계약 변경이 없다.

### 3.4 Data 레이어 테스트

| 테스트 ID | 설명 | 기대 결과 | 보호 규칙 |
|---|---|---|---|
| `T-DAT-001` | 입력 저장 후 동일 입력 로드 | 값 완전 일치 | `R-DAT-001` |
| `T-DAT-002` | 결과 저장 후 동일 결과 로드 | 길이/순서 일치 | `R-DAT-002` |
| `T-DAT-003` | 존재하지 않는 ID 로드 | `DATA_NOT_FOUND` | `R-DAT-003` |
| `T-DAT-004` | 손상된 파일 포맷 로드(File 옵션) | `DATA_FORMAT_ERROR` | `R-DAT-004` |
| `T-DAT-005` | 저장 시 4x4 불변조건 위반 데이터 거부 | `INVALID_MATRIX_SIZE` | `R-DAT-005` |

데이터 규칙:
- `R-DAT-001`: 저장/로드는 입력 행렬 순서와 값을 보존한다.
- `R-DAT-002`: 결과 배열은 길이 6과 인덱스 순서를 보존한다.
- `R-DAT-003`: 없는 식별자 요청은 명시적 not-found 오류를 반환한다.
- `R-DAT-004`: 포맷 오류는 읽기 실패와 구분된 코드로 반환한다.
- `R-DAT-005`: Data 계층은 4x4 불변조건을 우회 저장하지 않는다.

## 4) Integration & Verification (통합 및 검증)

### 4.1 통합 경로 정의

의존성 방향:
- `UI Boundary` -> `Application Service(선택)` -> `Domain Services`
- `Application Service(선택)` -> `Data Repository Interface`
- `Data Adapter(InMemory/File)`는 인터페이스 구현체로 바깥 레이어에 위치

규칙:
- Domain은 UI/Data 구현체를 참조하지 않는다.
- UI는 Domain 내부 규칙 세부 구현을 알지 못한다.
- Data Adapter 교체 시 UI/Domain 계약은 변경하지 않는다.

### 4.2 통합 테스트 시나리오

정상 시나리오(2개 이상):

| 테스트 ID | 시나리오 | 기대 결과 |
|---|---|---|
| `T-INT-001` | 유효 입력 -> Domain 성공 -> UI 성공 응답 | `int[6]` 반환 |
| `T-INT-002` | 유효 입력 저장 후 재로드 -> 재실행 | 동일 결과 재현 |

실패 시나리오(3개 이상):
